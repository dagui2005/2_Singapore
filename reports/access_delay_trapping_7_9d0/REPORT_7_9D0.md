## 0. 一句话结论

**「延误被困在接入子系统」这个说法在数值上成立，但在因果上被误读了。** 真正的事实是：

> 延误根本**不在主线接口上**（仅 **3.19%** 的延误落在主线邻域内）。C-1 观察到的「`service` 吃掉 94.36% 延误」是一个**网络构成（base-rate）假象**——v1.0 里 `service` 占 **64.95%** 的 link、**58.61%** 的 km，而 **90.26%** 的出行起终点就落在这类「车道」上。
> 三条接口审计的结果是：**① 单向阀不存在（证伪）② 薄储存成立、但它是查表赋值而非涌现 ③ 排队耦合的缺失不是被"阀"切断，而是被"距离"隔开（延误加权上游距主线 ≈ 1.95 km）。**

## 2. 决定性发现 ①：Base-rate 控制让结论**反转**

C-1 是在**全网口径**下读「`service` 占 94.36% 延误」的。D-0 强制先做共同因子证伪：

| class | 全网 km% | 全网 link% | 全网 delay% | **全网 ratio** | 邻域 km% | 邻域 delay% | **邻域 ratio** |
|---|---|---|---|---|---|---|---|
| motorway | 3.73% | 1.42% | 2.50% | 0.671 | 80.15% | **78.42%** | 0.978 |
| ramp | 2.04% | 1.69% | 1.46% | 0.719 | 11.23% | **17.93%** | **1.597** |
| connector | 1.07% | 1.98% | 0.11% | 0.104 | 0.02% | 0.00% | 0.000 |
| **service** | **58.61%** | 64.95% | **94.36%** | **1.610** | 3.10% | **0.53%** | **0.171** |
| other | 34.56% | 29.96% | 1.57% | 0.045 | 5.50% | 3.12% | 0.566 |

**读法**：
1. 全网 `service` 的 ratio 只有 **1.610**（< RATIO_CONC 2.50）⇒ **不构成"强烈富集"**，只是略高于其 km 占比。
2. 一旦**限定在主线邻域**，`service` 的 ratio 掉到 **0.171** ⇒ **在主线接口上，`service` 是"欠表达"8.5 倍**，而不是富集。
3. 邻域内延误的 **96.35%** 落在 `motorway` + `ramp` 上 ⇒ **贴主线的那一小块延误，本来就长在快速路和匝道上**。

**旗标**：`BASE_RATE_ARTIFACT = True`（由邻域 ratio 0.171 ≤ 1.50 触发）。

> ⚠️ 这一条直接修正了 C-1 的因果叙事：**不能说「接入子系统在主线上吸延误」，只能说「主线上本来就没多少延误可供吸」。**

**补充（非预注册）—— 细分辨率检验**：按 `(highway × lanes)` 分组

```
13 种 highway 类型，non-deterministic = NONE (全部 lookup-assigned)
```

## 6. D4 — 延误的真实来源：**出行的两端都挂在 `service` 上**

（描述性，**无裁决权**；来源 = 冻结输入人口 `pop_W01/population_lambda_0p075.xml.gz`，**未使用** `output_plans` / `linkstats`）

| 量 | 值 |
|---|---|
| 映射到网络的出行数 | **236,044** |
| 起点落在 `service` | **0.7068** |
| 终点落在 `service` | **0.6685** |
| **至少一端落在 `service`** | **0.9026** |
| 对照：`service` 的 km 占比 | 0.5861 |

起点分布：`service` 0.7068 / `other` 0.2708 / `ramp` 0.0107 / `connector` 0.0094 / `motorway` 0.0023。

**机制闭合**：`service` 只占 58.61% 的 km，却承载 **70.68%** 的起点、**66.85%** 的终点 ⇒ 每趟车的首/末 link 都极可能是一条 **400 veh/h/车道、20 km/h、≈1.55 车储存**的「车道」。
⇒ **延误在出行两端被就地生成、就地消化；它离任何主线还有约 1.95 km（见 §7）——更准确的说法是：在当前网络拓扑与 QSim 表征下，延误向主线反向传播的有效耦合很弱**（这是一个**模型结构事实**：`d_up>3` / 1,952 m / `≤300 m` 仅 3.15%；**不是**数学上「永远不能回溢」的证明）。

## 8. 判决与旗标

```
VERDICT = DELAY_TRAP_OFF_MAINLINE_BY_CONSTRUCTION__BASE_RATE_DOMINATED
VERDICT_RULE = branch2: share_off=0.9722 >= 0.90

FLAGS:
  VALVE_PRESENT      = False   (sink_valve_share_interface = 0.00099)
  THIN_STORAGE       = True    (share fill<30s in interface = 0.8981)
  CAP_DETERMINISTIC  = False   (预注册类别级口径；细分辨率下为 True，见 §7.2)
  COUPLING_ABSENT    = True    (share_off = 0.9722)
  BASE_RATE_ARTIFACT = True    (邻域 service ratio = 0.171)
```

**判决的完整表述**：

> 延误之所以「被困在接入子系统」，**不是因为接入子系统在主线接口处把它们困住了**，而是因为（i）网络里 65% 的 link / 58.6% 的 km 是 `service`，（ii）**90.26% 的出行端点**落在 `service` 上，（iii）这些 link 的容量/速度/储存是**查表硬编码**的低值。三者叠加，使延误在**离主线 ~2 km 的出行两端**被就地生成、就地消化，**结构上根本没有机会接触主线**。
> **因此「主线—接入耦合缺失」是一个构造性事实（假象层面），而不是一个可修复的拓扑缺陷。**
