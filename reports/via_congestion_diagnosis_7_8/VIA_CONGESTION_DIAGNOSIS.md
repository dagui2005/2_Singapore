# 为什么 VIA 里看早高峰「一点儿都不拥堵」？—— 三层诊断

> 只读派生报告。**不构成新版本**：模型仍为 `Singapore_OD_MATSim_Final_v1.0`，
> `Sim/Obs = 0.9993347697`，冻结产物一字未动。
> 本目录仅由 `scripts/od/diagnose_via_congestion_7_8.py` 生成，
> 两表（linkstats / network attrs）已按 `link id` 显式对齐并内建 `LENGTH` 一致性断言。

数据源：`matsim_viz_7_8/outputs/W01_events/`（7.8-VIZ-RUN 输出层重执行，已判 `BITEXACT`）。

## 直接结论

不是你看错了，也**不是**「模型没跑对」。是**三层原因叠加**：

| 层 | 原因 | 关键证据 |
|---|---|---|
| **① 可视化层（主因）** | VIA 的 **Network 层本身不带任何交通属性**。要出流量/速度，必须**另加 `Dynamic Link Attributes` 层**（VIA 手册 §3.2.5）；否则「Link 颜色」下拉里只有 `freespeed / capacity / lanes / length` 这些**静态**字段 —— **`freespeed` 是设计速度，与拥堵无关**，全市自然画成一片「畅通色」。 | 供 VIA 的 `output_links.csv.gz` 只有 10 个字段：`link, from_node, to_node, length, freespeed, capacity, lanes, modes, vol_car, geometry` —— **无任何行程时间 / 速度 / 延误字段** |
| **② 路网表征层** | 路网被切成 **693,575 条碎段**（长度中位数 **11.0 m**，均值 21.8 m）；全市只有 **23 条 > 1 km**。全市尺度渲染时**单条路段小于 1 像素**，肉眼无法分辨哪段慢。且 MATSim 行程时间**按整秒存储**，几米路段的自由流时间不足 1 秒 ⇒ 短段「拥堵倍率」被严重放大。 | <20 m 路段占载流路段的 **63%**（条数），体量加权倍率 **1.76**；而 ≥200 m 路段倍率仅 **1.02–1.06** |
| **③ 模型层（真实情况）** | 模型**确实只有轻微拥堵**，且只集中在短碎段。**没有一条路段 v/c 超过 1.0**，容量富余；需求只有 23.6 万辆小汽车、全部 07–09 出发，峰时在途仅 3.68 万辆。 | v/c max = **1.000000**，>0.5 的仅 **1.22%** 路网 / **17.79%** 车流；剔除 ≤50 m 碎段后全网拥堵指数仅 **1.2091** |

## ① 可视化层：VIA 要「额外加一层」才会显示拥堵

VIA 手册 §3.2.5 **Dynamic Link Attributes** 原文要点：

> *"Displays traffic volumes or average link speeds by coloring the links in the network. **Requires a loaded network file and an events file.** This layer calculates two time-dynamic values for each link: (a) traffic volume, (b) average speed on a link... such that link volumes and link speeds can be selected as an attribute to display the network."*

所以正确做法是三步，缺一不可：

1. `Add Layer → Dynamic Link Attributes`（**不是** Network 层能替代的）→ 点 **Load Data**（解析 1.69 GB events，需数分钟）；
2. 把该层的 **aggregation window 设成 08:00–09:00** —— 全部需求只在 07–09，其他时段是空网；
3. 回到 **Network 层 → Link Coloring**，把属性从 `freespeed` 改成 **`speed`**（或 volume）。

若按 **volume** 着色也不容易看出堵：容量普遍很大（v/c 中位数仅 **0.0236**），颜色会普遍偏冷。**要显示拥堵请按 speed（或相对速度）着色。**


## ② 路网表征层：693,575 条碎段

| 指标 | 值 |
|---|---|
| 有向路段数 | **693,575** |
| 路段长度中位数 / 均值 | **11.0 m** / **21.8 m** |
| 总长度 | **15,126.5 km** |
| > 200 m / > 500 m / > 1,000 m 的路段 | **3,463** / **167** / **23** |
| 单车道（lanes=1）路段占比 | **51.1%** |
| 长度加权：一次通勤平均经过 | **≈ 342 条路段 ≈ 7.5 km** |

长度中位数 11 m 意味着**一条真实道路被拆成几十段**。后果有二：
- **渲染上**：全市视角下 693k 条线叠成一层网，单段亚像素，颜色分不出来；
- **指标上**：MATSim linkstats 的行程时间是**整数秒**，11 m 路段自由流时间 ≈ 2 s，任何一秒的排队都让倍率翻倍 ⇒ 短段的「拥堵倍率」是**量化噪声**，不是拥堵。

### 拥堵倍率 × 路段长度（08–09，有流量路段）

| 长度区间 | 路段数 | 体量加权倍率 | 中位倍率 |
|---|---|---|---|
| 0–20 m | 142,265 | 1.757 | 1.520 |
| 20–50 m | 57,203 | 1.311 | 1.169 |
| 50–100 m | 19,639 | 1.162 | 1.075 |
| 100–200 m | 4,577 | 1.096 | 1.045 |
| 200–500 m | 719 | 1.064 | 1.025 |
| >500 m | 29 | 1.018 | 1.013 |

**倍率随长度单调塌缩**：短段最高 → ≥200 m 段仅 1.0x。这正说明「堵」几乎全是短段伪影（倍率截断至 2.5 以抑制极值）。

### ★ 「堵的很多」≠「看得见」—— 换个口径结论就反了

同一批载流路段，**按条数**统计「过半数超 1.2」，**按长度**统计却只有约三分之一：

| 拥堵倍率 | 按**条数**占比 | 按**长度**占比（≈视觉面积） |
|---|---|---|
| ≤1.2 | 42.6% | 66.3% |
| 1.2–1.5 | 23.7% | 22.2% |
| 1.5–2.0 | 17.6% | 8.6% |
| >2.0 | 16.1% | 3.0% |

地图为什么会「偏绿」：长路段（视觉占主导）恰好都是自由流，而高倍率的全是几米长的短段 —— 在屏幕上连一个像素都不到。

## ③ 模型层：真实拥堵其实很轻，且从未打满容量

| 指标（08–09） | 值 |
|---|---|
| 全网拥堵指数（全部路段） | **1.4143** |
| ↳ 剔除 ≤20 m | **1.2671** |
| ↳ 剔除 ≤50 m | **1.2091** |
| ↳ 剔除 ≤100 m | **1.1082** |
| 延误车时（全部路段） | **10,319 车时** |
| 体量加权车速 / 自由流车速 | **46.6** / **65.9** km/h |
| 平均单次通勤时间 | **8.95 min** |
| **v/c = HRS8-9avg ÷ CAPACITY** | max **1.000000**；>1.0 的路段 **0** 条 |
| ↳ v/c > 0.5 | 路段 **1.22%** · 车流 **17.79%** |
| 流量最大路段 | 9,034 辆/h · 5 车道 · 自由流 90 km/h · **v/c = 0.951** |

**需求侧**：`W01/it.19` 共 **236,044** 辆小汽车，**全部在 07:00–09:00 出发**（07 时 114,970 · 08 时 121,074），峰值同时在途 **36,799** 辆。摊到 15,126 km 路网 ≈ **2.4 辆/km**。

而这已经是**本项目的既定口径差**：观测 `Volume` 是**全机动车 + 全目的**，MATSim 侧只做**小汽车通勤** ⇒ 仿真需求本来就只覆盖真实早高峰的一个子集（见项目记忆 §2「观测无车型字段」）。

## 所以：想真的「看见」拥堵，怎么做

**A. 在 VIA 里（推荐）** —— 见上文 ①，核心是加 `Dynamic Link Attributes` 层，把窗口设到 08–09、颜色属性改成 `speed`。

**B. 用本目录给出的校准级属性文件**（免解析 events）：

- `via_link_attributes_HRS8-9.tsv` —— 首列 `link`，含 `cong_ratio_0809 / speed_kmh_0809 / load_vc_0809 / delay_s_per_km_0809 / vol_0809`（及 07–08 同套）；直接由 **it.19 linkstats** 算出，口径与冻结评价值一致。

- 加载：Network 层设置里的 **小三角 → Attributes Manager… → 选择该 TSV**（VIA 支持 TSV/CSV 对象属性）。建议按 `speed_kmh_0809` 着色。

- `congestion_map_and_diagnostics_HRS8-9.png` —— 离线总览图（A/B 两幅地图 + C 倍率×长度 + D 条数vs长度 + E 出发时刻 + F v/c + G 指数塌缩）。


**C. 期望管理**：即便颜色对了，你看到的也**不会**是「全城飘红」。本模型 08–09 的拥堵指数在剔除碎段后只有 **1.2091**，且 v/c 从未破 1 —— 真实的红色只会零星出现在少数干道短段上。**要更堵，需要的是模型层面的结构修复（`7.9 Structural Repair / v1.1`），而不是调可视化。**
