## 0. 结论先行（TL;DR）

1. **原稿脚本有 1 处致命 bug + 1 处方法学缺陷**：`sim.merge(e, on="LINK")` 列名不匹配会直接 `KeyError`；"质心大半径 + 求和"使每个断面挂 **77** 条边，`sim_obs_ratio` 被抬到 **16.90**（纯伪影）。
2. **修正后（沿线采样 + 路名一致 + 逐断面中位数）**：8 条边/断面，`sim_obs_ratio = 0.618`、`r = 0.293`。
3. **关键判断：crosswalk 重构并没有改善快速路低估。** CATA（快速路）比值 **0.515**（6.3 为 0.510）、断面内相关 **r ≈ 0**；三口径（median/mean/max）下 CATA 相关都 ≈0。
4. 因此 **6.3 暴露的"快速路低估 + 断面内零相关"是真实的模型/分配信号，不是观测 crosswalk 粒度造成的**。crosswalk 只纠正了"求和口径伪影"，未提升拟合质量。
5. 让 6.3.2 **仍不解决**"全部 agent 08:00 同时出发"的**时间脉冲**问题 —— 那是独立的 **6.3.3 Departure-Time Profile**。

## 1. 对照口径

```
LTA LinkID --(TrafficFlow_Links.shp 几何)--> 断面沿线候选 OSM 边
    --(network_links_source_copy.csv 行号)--> MATSim link e{from}_{to}
    --> 逐断面汇总 sim 流量 --> 与 LTA observed flow 比较
```
- 观测宇宙：`TrafficFlow_Data.json` 的 **1,278** 条链路（全量 1,311；工作日 hour ∈{7,8}，n≥5）。
- 观测口径：`obs_am = obs_h7 + obs_h8`（中位数日聚合）。
- 仿真口径：`sim` 取 linkstats `HRS8-9avg`（全部需求 08:00 一次性释放 → AM 脉冲集中在 8–9 点）× 规模 `scale = 459794/200000 = 2.29897`。
- 交叉核验：本脚本重算 obs 中位数与 6.3 一致。

## 2. 运行前修复的缺陷

### 2.1 致命 bug（会直接崩溃）
```
e = edges[["matsim_link_id"]].reset_index(names="osm_edge_index")   # 列: osm_edge_index, matsim_link_id
sim2 = sim.merge(e, on="LINK")                                      # sim 的键是 LINK，e 没有该列 → KeyError: 'LINK'
```
修正：把 `matsim_link_id` 重命名为 `LINK` 后再 merge。

### 2.2 方法学缺陷（结果不可用）
- **过度纳入**：每个断面用"质心 120m（全部边） + 250m（同名边）"→ **中位 77 条边/断面**（最多 264），把**平行道路、对向车道、邻接走廊**全拉进来（仅 30.5% 路名匹配）。
- **汇总口径错**：对 ~77 条边**求和**。但
  - LTA `Volume` 是**点计数**（每小时通过某断面的车数）；
  - 同一走廊的**顺序** OSM 边在稳态下流量相近 → **求和 = 流量 × 边数** ✗；
  - 跨断面求和还会因车辆被每个断面重复计数而**二次膨胀**。
  → 正确估计量 = 断面内**同向顺序边的代表值（中位数）**，逐断面独立比较，**不跨断面求和**。

## 5. KPE 专项诊断（"点计数 vs 求和"的直接证据）

| 指标 | 数值 |
|---|---:|
| 全网络 KPE 边（name≈KALLANG PAYA LEBAR EXPY） | **483** |
| 仿真 KPE 全网流量（scaled 求和） | **451,757** |
| 观测 22 个 KPE 断面之和 `obs_am` | **450,748** |
| 比值（全网求和） | **1.00** |
| 仿真 KPE **单条边**最大流量（scaled） | **4,584 /h** |
| 观测断面中位流量 | **17,969 /h** |

**解读**：
- 把整条 KPE 的仿真流量**全网求和**（451,757）恰好等于**所有断面观测求和**（450,748）—— 但这是**巧合**：两者都把同一辆车在每个"网格/断面"记一次，量纲相同却**与断面点流量不是一回事**。
- 逐断面看，仿真**单点流量仅 4,584/h（最大边）** vs 观测 **~18,000–34,000/h** → **KPE 点流量偏低约 4–20×**。
- 说明 6.3 里"KPE 只捕获 3.3%"**不是单纯映射错误**：KPE 确实被**系统性少分配**（地下快速路，可能因 AM 阻抗/连通/OD 结构）。

## 6. 为什么"crosswalk 粒度"不是主因

| 证据 | 含义 |
|---|---|
| 修正后总量比 0.618 vs 6.3 的 0.647 | 断面重构**不改变**总体拟合 |
| CATA ratio 0.515 vs 6.3 的 0.510 | 快速路低估**原样保留** |
| CATA r ≈ 0（三口径一致） | 快速路的**空间分布**与观测无关，非映射造成 |
| SLIP_ROAD 1.4–2.8× 保留 | 匝道高估是**模型行为** |

→ 6.3 的主要问题**不是**观测 crosswalk 的粒度，而是**分配侧**（routing / OD 结构 / 网络连通 / 出发时刻脉冲）。crosswalk 重构的价值在于：**排除**了这一疑点，并给出一套可复用的**断面级对照基线**。
