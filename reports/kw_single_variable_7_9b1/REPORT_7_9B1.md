## 1. L1 — 有没有产生动力学变化？**有，而且很大**

| 指标 | v1.0（queue） | 7.9B-1（kinematicWaves） | 变化 |
|---|---|---|---|
| **Sim/Obs（FROZEN, Q̄₁₀:₁₉）** | **0.9993348** | **0.8506114** | **−14.9%**（崩解护栏 ≥0.85，**险过**） |
| Sim/Obs（it.19 单点） | — | 0.8603917 | — |
| `v/c ≥ 1` 饱和链路 | 82 link / **1.151 km** | 10 link / **0.271 km** | ↓（★见下注） |
| 真实超额 > 0.1 链路 | 4,705 link / 58.19 km | **18,860 link / 200.87 km** | **4.0× 链路 / 3.5× 里程** |
| **总延误车时** | **4,778.8 h** | **12,482.1 h** | **+7,703 h（+161.2%）** |
| 稳定性 `A_10:19`（MATCHED） | 0.8899% | **3.5200%** | 恶化 4.0× |
| `parity_gap_rel` | 0.0964% | 0.3757% | 恶化 3.9× |
| FD 入口上限 `r_fdiag<1` | — | 21,670 link / 869.6 km | 7.9B-0 已预登记 |

**★关键判读（防误读）**：`v/c ≥ 1` 的链路从 82 降到 10，**不是**「拥堵减轻」，而是 **KW 把流量削下来了**——`Sim/Obs` 掉了 15%，本来贴着容量运行的链路整体跌破 1.0。真正反映拥堵的**延误型指标**（超额、延误车时）**反向暴涨**。这就是「**流量掉了、时间长了**」——KW 的典型签名。

**次级观察（附警示）**：08–09 小时均值恰好落在 FD 入口天花板上的链路数 KW = **0** vs v1.0 = **32**。
⚠️ 该指标是**巧合级**度量（`q_fdiag` 是「速率上限」，小时均值天然低于它），**不得**据此说 KW 约束无效——运行期告警已证明约束**生效**。它的正确读法是：**KW 的入口约束表现为「排队等待」，而不是「把小时流量压在天花板上」**，因此延误上升、`v/c` 饱和反而下降。

## 2. L2 — 有没有形成真正的连续拥堵？**新增拥堵更弥散，没有长出长链**

按 `isolated links → short chain → junction clusters → connected components` 四尺度聚合（链路按共享节点做有向连通分量）：

| 尺度 | v1.0（queue） | 7.9B-1（KW） | 读法 |
|---|---|---|---|
| 饱和集合 分量数 | 82 link / **16 分量** / 最长 0.403 km | 10 link / **3 分量** / 最长 0.111 km | 饱和集合本身被流量削小 |
| **超额集合 分量数** | 4,705 link / **3,603 分量** | 18,860 link / **8,223 分量** | **碎片数 2.3×** ⇒ 变**更碎** |
| **超额集合 最长分量** | **0.857 km** | **0.954 km** | 仅 +11%，**没有长链** |
| 命中 junction-cluster 单元（超额） | 2,283 / 22,722 | 3,788 / 22,722 | 集合大了 4×，命中只大 1.7× |
| **★超额链路落在「候选结构单元」内的比例** | **32.54%** | **29.45%** | **下降** |
| **★相对 base(18.94%) 的富集** | **1.718×** | **1.555×** | **下降** |

**判决**：KW 让超额链路数量翻两番，但它们是**更多、更短的碎片**（分量 3,603 → 8,223，最长分量仍 <1 km），并且**落在结构瓶颈候选单元内的比例从 32.5% 降到 29.5%（富集 1.718× → 1.555×）**。
⇒ **「isolated → short chain」成立了，「short chain → junction cluster → component」没有成立。** 这正是 7.9B-0 预言的 **「KW 对高速路段均匀削流、不修瓶颈位置」** 的宏观表现：**变堵 ≠ 堵得对**。

## 5. 红线遵循情况（★机制变化 vs 位置改善，严格分离）

| 判据 | 结论 | 证据来源 |
|---|---|---|
| **① 「KW 改变了拥堵传播机制」** | ✅ **成立** | **仿真结果即可验证**：Δ延误 +7,703 h、Δ超额里程 +142.7 km、Δ分量 +4,620、Δ稳定性 +2.63 pp；运行期 FD 入口告警 |
| **② 「KW 让拥堵位置更接近真实结构瓶颈」** | ❌ **不成立** | **必须** C3/C4 空间证据，而 C3 lift 1.852×→1.835×、C2 ρ +0.0267→−0.0078（p 0.20→0.485）、超额落候选单元比例 32.5%→29.5%（富集 1.718×→1.555×）、辅助口径 1.679×→1.601× |

⇒ **B-1 的真正成功标准不是「比 queue 更堵」，而是「产生动力学差异 且 该差异具有可解释的空间结构」**。本例**满足前者、不满足后者**，故裁决为 **`KW_POSITION_NOT_IMPROVED`**。

**稳定性备注**：`A_10:19` 从 0.89% 升到 **3.52%**，仍在 5% 门内（`STABILITY_OK`），但已**明显恶化**；`Sim/Obs` 落到 **0.8506**，几乎贴住 0.85 护栏 ⇒ KW 把「流量损失预算」几乎用尽。⚠️ 该 15% 流量损失是 **`SCALE` 未在 KW 下重标定**造成的口径后果；**按 7.6F-1 纪律，禁止用 `ΣEF/N_sim` 重算 `SCALE`**，故如实报告、不做补偿。

## ★ 更正附录（2026-09-20，由 7.9C-1 检出）

**更正**：本报告正文中的「**CTE 走廊仅 1.76 → 24.22 h（0.19%）**」**并非 CTE**。

- v1.0 网络 `name` 字段中**不含**字面 `CTE`（0 条 link）；分析脚本的掩码 `"CTE" in name.upper() or "CHANGI" in ... or "TAMPINES EXP" in ...` 实际命中 **Changi ∪ Tampines Expressway**（3,647 link）。
- **CTE 正名 = `Central Expressway`（603 link / 34.55 km）**，其延误为：

| 掩码 | link | v1.0 延误 h（占比） | KW 延误 h（占比） |
|---|---|---|---|
| **CTE 正名（Central Expressway）** | 603 | **104.570（2.19%）** | **56.680（0.45%）** |
| Changi（掩码命中） | 3,148 | 1.652（0.03%） | 11.359（0.09%） |
| Tampines Expressway（掩码命中） | 499 | 0.107（0.00%） | 12.860（0.10%） |
| **旧掩码合计（= Changi ∪ Tampines）** | 3,647 | **1.759（0.04%）** | **24.218（0.19%）** |

**结论影响**：**三层裁决与 verdict 不变**（延误主体仍是 `service` 88–94%，KW 位置未改善）。但「KW 未复现唯一真实的快速路排队链」一句的**数值须更正**：正名下 CTE 在 v1.0 有 **104.57 h（2.19%）**、**KW 下降到 56.68 h（0.45%）** ⇒ KW 不是「没复现」，而是**削弱/转移**了唯一真实快速路排队链。详见 `reports/structural_spillback_7_9c1/REPORT_7_9C1.md` §6。
