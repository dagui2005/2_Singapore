---

## 1. 问题与边界

7.9D-0 把研究对象由 `service + connector` **收窄**到 `mainline ↔ ramp ↔ local-access`，理由是 `ramp` 是主线接口邻域**唯一相对富集**类（邻域 `ratio` **1.597**）。本步回答：**这个富集是不是一个真正的接口机制？**

⛔ 不重答 D-0；⛔ 不改任何冻结件；⛔ 不产生 v1.1。

## 2. 判据规则（本步起永久生效）

- **R-DIST-1（物理距离优先）**：接口距离一律以 **meter/km** 为主口径，hop 仅作拓扑辅助。
- **R-MULTI-1（多跳优先）**：接口/相邻/耦合判据**不得**只用单跳邻接。

## 3. 结果

### 3.1 单跳口径是近重言式（必须先排除）

`motorway_link`/`trunk_link` 共 **11,740** 条（**308.15 km**），但按单跳邻接分类：

| 单跳类型 | 条数 | 占比 |
|---|---|---|
| `neither`（`frm` 无 mw 入边 且 `to` 无 mw 出边） | **10,886** | **92.73%** |
| `on_ramp`（`to` 有 mw 出边） | 428 | 3.65% |
| `off_ramp`（`frm` 有 mw 入边） | 422 | 3.60% |
| `both` | 4 | 0.03% |

⇒ **旗标 `SINGLE_HOP_TAUTOLOGY = True`**（neither ≥ 0.80）。与 D-0 的 K3 完全同型：**单跳口径必然给出 ≈100% 的「不接触」**，无信息量。故本步主口径改为多跳物理距离。

### 3.2 多跳物理接口（主口径）：连续，但 ramp 是一条 ~478 m 的碎片链

| 量 | 全 link | ramp |
|---|---|---|
| `acc_m`（到主线的最短免费流弧长） | 中位 **1,709 m** | 中位 **478 m**，p90 **1,467 m** |
| `≤300 m` | — | **30.49%** |
| `>1000 m` | — | **20.92%** |
| `egr_m`（从主线驶出的最短免费流弧长） | — | 中位 **419 m** |
| 距离场有限率 | **100.00%** / **100.00%** | — |

⇒ **从任意 ramp 片段沿行驶方向 100% 可达主线**；不存在「无路可通」的断裂。ramp 的「远」不是因为断链，而是因为**一件 ramp 被切成许多片段**：

| ramp 链长 | 值 |
|---|---|
| 到主线残余链长（中位 / p90） | **500 m** / **1,491 m** |
| 单个片段长度（中位） | **16.6 m** |
| 片段 ≤20 m 的比例 | **58.29%** |

### 3.3 车道 / 容量连续性：几乎无缺陷

对 **432** 个 `on_ramp` 片段（合流侧）：

| 量 | 值 |
|---|---|
| `Δlanes = min(下游 motorway 车道) − ramp 车道`（中位 / min / max） | **+2** / **−2** / **+6** |
| 合流处**车道下降**（`Δlanes < 0`） | **8** 条（**1.85%**，阈值 0.20 未触发） |
| `Δcap_per_lane`（motorway − ramp，中位） | **+200** veh/h/车道 |

⇒ 主线在合流处**普遍比 ramp 宽 2 车道、每车道多 200 veh/h**，这是正常的**合流扩容**，不是「瓶颈收窄」。`LANE_DROP = False`。
`ramp` 的 `cap/lane` 在**每一类 highway 内唯一**（`motorway_link` 1 值、`trunk_link` 1 值）⇒ **`CAP_DETERMINISTIC = True`**（纯查表赋值，同 7.9D-0）。

### 3.4 ramp 的延误：几乎不存在

| 量 | v1.0 | KW |
|---|---|---|
| ramp 延误 | **69.9 h**（share **1.46%**） | 220.7 h（share 1.77%） |
| ramp 里程份额 | **2.04%** | — |
| **`ratio = delay_share / km_share`** | **0.719**（**< 1 ⇒ 欠表达**） | — |
| ramp **车流份额** | **9.22%** | — |
| 单位车流延误份额（share / vol_share） | **0.158** | — |
| motorway 延误 | **119.6 h**（share **2.50%**） | — |
| 有延误的 ramp 片段数（>0.01 h） | **228** | — |
| 其到主线的**延误加权**接入距离 | **647 m** | — |
| 其中 `≤300 m` / `>1000 m` | **26.75%** / **23.25%** | — |

⇒ **ramp 是全模型最畅通的链路之一**：占 9.22% 的车流，只产生 1.46% 的延误（按车流归一后 **0.158**，即比全网平均低 6.3 倍）。7.9D-0 观察到的「邻域 `ratio` 1.597」是**邻域局部相对量**，在绝对量级上**不构成延误机制**。

### 3.5 ramp 的局部储存

| 量 | 值 |
|---|---|
| 单片段储存（中位 / p90） | **3.28** / 13.15 车 |
| 下游节点 `fill_time`（中位 / p10，n=11,386） | **4.96 s** / 1.37 s |

⇒ ramp 的储存与 D-0 的 `service` 同属**薄储存**，但其**绝对延误贡献可忽略**。

## 4. 判决与判读

判决分支（PREREG §6 第 3 支）：`ramp_share = 0.0146 < 0.05` **且** `delay_weighted_acc_m = 647 m ≤ 1000 m`
⇒ ### `RAMP_INTERFACE_CONTINUOUS__RAMP_NOT_A_DELAY_HOST`

**判读**：
1. **接口连续**：任意 ramp 片段 → 主线 **100% 可达**；合流处车道/容量**向上扩容**，车道下降仅 1.85%。
2. **ramp 不是延误机制**：延误 1.46%、`ratio` 0.719、按车流归一 0.158。即便**全部** ramp 延误都传进主线，也只有 69.9 h（占全网 1.46%），**不足以解释主线拥堵缺失**。
3. **「ramp 富集」是邻域局部相对量**：D-0 的邻域 `ratio` 1.597 建立在一个**极小绝对基数**上；把它读成「ramp 是接口瓶颈」是**规模错觉**（与 D-0 对 `service` 的 base-rate 解构同型，只是方向相反）。

## 5. 对用户假设的诚实回应

> 用户提问：`ramp` 是否是目前唯一值得继续追的接口类别？ramp 延误是否真正能传到 motorway？

**答案：接口本身没有问题，ramp 也不能构成延误机制。**

- ramp 延误**在物理上确实靠近主线**（延误加权 **647 m**，26.75% 在 300 m 内）⇒ **耦合方向上是通的**；
- 但**量太小**（1.46%），因此「ramp 没能把压力传回主线」不是一个可成立的机制解释。

⇒ 与 7.9C-1 / 7.9D-0 连续两次的结论一致：**问题不在主线接口层，也不在接驳层的拓扑缺陷**。

## 6. 预注册缺陷的如实上报（不得掩盖）

`R1.05` / `R1.06` **FAIL**，但**与数据无关**：

- 冻结门文写的是「`finite≥0.999` **且 `min>0`**」。而 `acc_m`/`egr_m` 的**种子就是全部主线 link**，其距离**按构造恒等于 0** ⇒ `min>0` 是**逻辑不可能条件**。
- 观测：`finite = 1.0000`、`min = 0.0`。距离场本身**完全良构**。
- **处理**：**不改动已冻结的预注册**（其 sha256 不变），改为并列**补充门**：
  - `S1.01` **PASS**：`finite=100%` 且 **主线种子 `==0`** 且 **非主线 `>0`**；
  - `S1.02` **PASS**：同 `S1.01`（egress）；
  - `S1.03` **PASS**：`cap/lane` 在 ramp 的每类 highway 内确定（`motorway_link` 1 / `trunk_link` 1）。
- 判决分支只用 `finite < 0.99`（为 False），**与 `min>0` 无关** ⇒ **verdict 不受影响**。

> **教训**：预注册里的「完整性判据」必须写成**良构形式**（种子值 + 非种子域），不能写「全域 min>0」——**物理距离场的主线种子必然是 0**。
