## 一句话总结

把新加坡全岛人口、住房、企业、车辆出行数据接进来，喂给交通仿真软件（MATSim），在电脑里"重演"早高峰车流，再用真实摄像头数据对账——校准出一个能代表真实交通的仿真模型 `Singapore_OD_MATSim_Final_v1.0`。

---

## 第一章：这个项目在做什么？

### 1.1 背景

新加坡每天早高峰有几百万次出行。规划新的地铁线、修新的高速路口、封路维修——这些决定都会影响真实车流。要事先知道某项决定会不会"添堵"，工程师通常先用电脑仿真来"跑一遍"看效果。

但仿真模型本身不是凭空变出来的，它必须**先校准**——也就是让仿真结果和真实路况数据对齐到"很像"的程度，才能拿去预测未来。

### 1.2 这个项目做了什么？

用新加坡的公开数据（人口普查、住房、企业、路网、实时交通量），按 14 步流水线，逐步搭建一个仿真模型，再用真实摄像头数据反复校准，最后**正式冻结**为 `Singapore_OD_MATSim_Final_v1.0`。

这个模型已经能够：
- 重现新加坡早高峰车流
- 仿真总流量和实测总流量一致到小数点后 3 位（差距仅 0.07%）
- 用于未来的"如果……会怎样"类政策评估

### 1.3 还没解决的问题

仿真在**全局量级**上和真实几乎完全一致，但在**空间分布**上还有偏差：

- 东部（EAST）仿真流量比实测**少约 32%**
- 东北部（NORTH-EAST）仿真流量比实测**多约 34%**

这种偏差是**结构性的**（不会因为再调参数消失），需要在 v1.0 之后的版本（v1.1 或 7.9 系列残差归因）解决。本期项目已决定：
- v1.0 不再修正（避免过度拟合）
- 等待外部数据（LTA 分车型交通量、HTS 出发时刻）到位
- **从归因入手，不从调参入手**

## 第三章：术语速查表（按拼音排序）

每个术语给三件事：
- **是什么**（精确定义）
- **通俗理解**（大白话）
- **在本项目中怎么用**（具体语境）

### A 开头

#### ACRA

- **是什么**：新加坡会计与企业管理局（Accounting and Corporate Regulatory Authority）的全岛公司注册数据。
- **通俗理解**：全岛"哪里是公司/工作地"的官方名册。
- **怎么用**：每个企业的注册地址 → 对应到一个空间小区 → 当作"出行终点"（吸引量 A_j）的来源。

#### Attraction（吸引量 A_j）

- **是什么**：每个空间小区早高峰时段"被多少人作为出行目的地"的数量。
- **通俗理解**：上班早高峰，每个小区"吸引"多少人来这里——工业区高、住宅区低。
- **怎么用**：用 ACRA 企业注册数据 + Census 出行调查 118 控制表推算。

### C 开头

#### Census（人口普查）

- **是什么**：新加坡 2020 年全国人口普查（含出行调查）。
- **通俗理解**：每 10 年一次的全岛人口大摸底——每户有几口人、怎么上班、怎么出行。
- **怎么用**：用出行调查的"早高峰起讫点"作为仿真结构是否合理的参照物。

#### Capacity Factor（容量系数 f_cap）

- **是什么**：在 MATSim 配置中给道路"通行能力"打的折扣系数，范围 0–∞。
- **通俗理解**：相当于"这条路能跑多少车"的乘数。`f_cap = 1.0` = 不打折；`f_cap = 0.5` = 一半通行能力。
- **怎么用**：本项目 `f_cap = 1.00`（冻结值），用作"采样一致性校正"——100k 人口 + `f_cap = 0.50` 等价于 200k 人口 + `f_cap = 1.00`。

#### Crosswalk（路段映射表）

- **是什么**：把"实测的 576 个摄像头断面"和"仿真里的路段 ID"一一对应起来的表格。
- **通俗理解**：翻译表——告诉系统"摄像头 A 看到的流量，对应仿真里的哪几条路"。
- **怎么用**：本项目用 `crosswalk = 7.3.6A`（最终冻结版，覆盖 96% 摄像头，纯度 100%）。

### D 开头

#### Demand Scale（需求缩放 f_demand）

- **是什么**：在仿真前给"出行需求总量"乘的一个系数。
- **通俗理解**：决定仿真里"跑多少车"。`f_demand = 1.20` = 比真实多 20% 的车。
- **怎么用**：本项目从需求响应扫描（7.4.3 系列）中确定最终 `f_demand = 1.180222`。

#### Distribution（大区）

- **是什么**：新加坡全岛划成 5 个大区（Region）：CENTRAL、EAST、NORTH、NORTH-EAST、WEST。
- **通俗理解**：把 332 个小区归类成 5 个"大块"。
- **怎么用**：用来分析"空间残差"——哪个大区的仿真值比实测高/低。

### E 开头

#### ExpansionFactor（扩样系数 EF）

- **是什么**：仿真里每个"虚拟人"代表的真实人口倍数。
- **通俗理解**：1 个虚拟人 ≈ 多少真实人。本项目 200k 虚拟人代表 ≈ 5925 真实人。
- **怎么用**：仿真输出流量 → 乘以 EF → 还原成"真实车流量"用于和实测对比。

#### EPSG:3414（SVY21）

- **是什么**：新加坡本地坐标系，用米做单位。
- **通俗理解**：相比经纬度（°）这种"全球统一但变形大"的坐标，本地坐标系"画图不扭"。
- **怎么用**：本项目所有空间数据（路网、小区、人口、企业）都统一用这个坐标。

### F 开头

#### FlowCapacityFactor（流量容量系数）

- **是什么**：MATSim 里"每小时最多能通过多少车"的乘数。和 `flowCapacityFactor` 一组。
- **通俗理解**：和 `f_cap` 类似，但作用于"动态"通行能力。
- **怎么用**：本项目冻结为 `1.0`。

#### FreeFlow（自由流 C^FF）

- **是什么**：道路在不拥堵状态下的理论通过时间（车都开得顺）。
- **通俗理解**：凌晨 3 点马路上没车时的通行时间——这是"基线"。
- **怎么用**：Step 4 算出每个 OD 对间的自由流通行时间矩阵。

### G 开头

#### Gravity Model（重力模型）

- **是什么**：借鉴万有引力公式——两个小区之间的出行量 ∝ (起点量 × 终点量) / 距离^衰减。
- **通俗理解**：两个小区之间"互相吸引"的强度——人多的 + 工作多的，距离越近，来往越多。
- **怎么用**：Step 5A 用"双约束重力模型"算初始 OD 出行量。

### H 开头

#### HDB（建屋发展局）

- **是什么**：Housing & Development Board，新加坡组屋管理机构。
- **通俗理解**：管全岛 80%+ 人口住的组屋。
- **怎么用**：HDB 2025 数据给出"哪栋楼有几户、每户几口人"。

#### HTS（家庭出行调查）

- **是什么**：Household Travel Survey，更细粒度的真实出行记录（小时级）。
- **通俗理解**：相比 Census 的"粗调查"，HTS 是"细调查"——几时出门、走哪条路。
- **怎么用**：本项目**还在等** HTS 数据，用来验证"早高峰时刻分布"。

### I 开头

#### IPF（迭代比例拟合）

- **是什么**：Iterative Proportional Fitting，一种"凑行/列和等于目标"的多维表调整算法。
- **通俗理解**：解数独的高阶版——保证每行每列加起来等于指定值。
- **怎么用**：Step 5A 用 IPF 让初始 OD 矩阵满足"每小区产生量/吸引量都等于推算值"。

#### Iteration（迭代）

- **是什么**：MATSim 仿真里"让虚拟车重新选路"的轮次。
- **通俗理解**：每跑一轮，所有虚拟车根据上一轮路况重新选路——20 轮之后基本稳定。
- **怎么用**：本项目 v1.0 跑 20 轮迭代。

### K 开头

#### K（计数基数错配 / 1:K 映射）

- **是什么**：一个实测摄像头断面在仿真路网上对应 K 条边。
- **通俗理解**：摄像头数"一辆车"，仿真数"K 条边都跑了一辆"——基数对不齐。
- **怎么用**：本项目 K 中位 5.54——7.9I 已证实这是空间残差主因。

### L 开头

#### λ（阻抗敏感性参数）

- **是什么**：重力模型里"距离对出行量影响有多大"的衰减系数。
- **通俗理解**：λ 大 = 距离影响小（人愿意跑远）；λ 小 = 距离影响大（人只跑近）。
- **怎么用**：本项目冻结为 `λ_ref = 0.075`（不是最优，是"敏感度中心"）。

#### LTA（陆路交通局）

- **是什么**：Land Transport Authority，新加坡交通主管部门。
- **通俗理解**：管全岛交通数据、规划、政策的机构。
- **怎么用**：LTA 17 类实时接口给"实测车流量"（校准标尺）。

### M 开头

#### MATSim

- **是什么**：Multi-Agent Transport Simulation Toolkit，开源的多智能体交通仿真软件。
- **通俗理解**：让"虚拟人"在"虚拟路网"上各自选路、各自跑的引擎。
- **怎么用**：本项目用 MATSim 2026.0 + Java 25。

#### M1 / M2 / M3（异常归因类别）

- **是什么**：Step 7.9H 给仿真-实测偏差归类的标签。
- **通俗理解**：M1 = 真·低载（车没跑）；M2 = median 塌陷（统计方法问题）；M3 = 信号缺失（基础设施未建模）。
- **怎么用**：本项目 7.9H 报告："仿真低 obs 高"几乎全是快速路，且大多由 M1 + M2 主导。

### N 开头

#### Node / Link（节点 / 边）

- **是什么**：路网的两个基本元素。Node = 路口 / 端点；Link = 一段路。
- **通俗理解**：节点 = 路口，边 = 路口和路口之间的一段路。
- **怎么用**：本项目仿真路网 421,770 节点 / 694,226 边。

### O 开头

#### OD（Origin-Destination，起讫点）

- **是什么**：一次出行的"起点 → 终点"。
- **通俗理解**：从 A 地出发到 B 地结束。
- **怎么用**：本项目算的是"早高峰 332×332 小区间的 OD 出行量矩阵"。

#### OSM（OpenStreetMap）

- **是什么**：开源全球地图协作项目。
- **通俗理解**：志愿者贡献的全球地图数据。
- **怎么用**：本项目用 OSM 给"路在哪里、几车道"的几何基础。

### P 开头

#### PermLanes（车道数）

- **是什么**：仿真里每条 link 的车道数。
- **通俗理解**：每段路有几条车道。
- **怎么用**：决定 link 的通行能力。

#### Population（虚拟人集合）

- **是什么**：仿真里所有"虚拟人"的集合。
- **通俗理解**：仿真的"演员名单"——每个虚拟人是一个 agent。
- **怎么用**：本项目 v1.0 用 236,044 辆虚拟车 × 早高峰。

### Q 开头

#### Q_sim / Q_obs（仿真流量 / 实测流量）

- **是什么**：同一条断面上的"仿真车流量"和"实测车流量"。
- **通俗理解**：仿真算出来多少车 / 摄像头数下来多少车。
- **怎么用**：两者比值 Sim/Obs 是校准的核心指标。本项目 v1.0 Sim/Obs = 0.999。

### R 开头

#### Region（大区）

- **是什么**：5 个大区（CENTRAL / EAST / NORTH / NORTH-EAST / WEST）。
- **通俗理解**：新加坡全岛分成 5 块。
- **怎么用**：空间残差分析的单位。

#### Route-Choice（路径选择）

- **是什么**：仿真里虚拟人怎么选路（最短时间？最便宜？）。
- **通俗理解**：每个虚拟人有个"路由策略"——遇到堵车怎么办。
- **怎么用**：本项目 v1.0 冻结 `R01_rc_min`（最小修复策略：ReRoute 0.15 + ChangeExpBeta 0.85）。

### S 开头

#### Section / Cross-Section（断面）

- **是什么**：路网上的一个"横截面"——仿真里的若干 link 对应一个摄像头断面。
- **通俗理解**：相当于"路上一道门"——车流过这道门时被数下来。
- **怎么用**：本项目用 576 个摄像头断面做校准。

#### Sim/Obs（仿真/实测比值）

- **是什么**：仿真流量 / 实测流量 的比值。
- **通俗理解**："仿真算出来多少"除以"实测多少"——接近 1 = 完美。
- **怎么用**：v1.0 全局 = 0.999（极佳）；分断面看仍有偏差。

#### SpeedRatio（车速比）

- **是什么**：仿真车速 / 实测车速 的比值。
- **通俗理解**："仿真里车开多快"除以"真实车开多快"——接近 1 = 仿真速度准。
- **怎么用**：用来验证仿真是否"该堵"——堵则速度低。

#### Subzone（子区）

- **是什么**：新加坡全岛 332 个最小空间单元。
- **通俗理解**：比规划区（55 个）更细，比街区更粗。
- **怎么用**：本项目所有"出行起讫点"的最小单元。

### T 开头

#### T_ij（OD 出行量）

- **是什么**：从 i 小区到 j 小区的早高峰出行数量。
- **通俗理解**：从家 A 到公司 B 有多少车。
- **怎么用**：本项目用 332×332 = 110,224 个 OD 对做矩阵。

#### TravelTime（通行时间）

- **是什么**：从 A 到 B 需要多久。
- **通俗理解**：开车 30 分钟、地铁 45 分钟——这就是通行时间。
- **怎么用**：本项目算"自由流通行"（不堵时）和"AM 峰通行"（堵时）。

### V 开头

#### v/c（饱和度）

- **是什么**：volume / capacity，路上车流量 / 通行能力。
- **通俗理解**：v/c < 1 = 路上没满；v/c > 1 = 超饱和，应该堵。
- **怎么用**：本项目用 v/c 来识别"应该堵但没堵"的路段。

#### v1.0（最终模型版本）

- **是什么**：`Singapore_OD_MATSim_Final_v1.0` 的简称。
- **通俗理解**：本项目的"1.0 正式版"——已经定版，不再修改。
- **怎么用**：所有"如果……会怎样"的预测都用这个版本跑。

### W 开头

#### WorkingPoint（工作点 / W01）

- **是什么**：v1.0 模型的"最佳参数组合"。
- **通俗理解**：`f_demand = 1.180222`、`λ = 0.075`、`f_cap = 1.00` ——这一组参数代表 v1.0。
- **怎么用**：7.6H 冻结后，所有"模型身份"都用这套参数。

### Z 开头

#### Zonal Aggregation（小区聚合）

- **是什么**：把仿真结果按小区（Subzone）汇总。
- **通俗理解**：把"路上一段一段"的车流数聚到"哪个小区"。
- **怎么用**：本项目用来分析"小区级"的车流分布。

## 第四章：方法详解（4 阶段 14 步）

### 第一阶段：算出"有多少出行需求"（用真实人口数据）

#### Step 1：数据接入与对齐

把上章列出的 7 类数据接进来，统一到同一坐标系（EPSG:3414）、同一时段（早高峰 07:00-09:00）、同一空间单元（332 个 Subzone）。

**这一步的难点**：不同数据用的空间单元不一样——HDB 用"组屋编号"、ACRA 用"邮编"、OSM 用"道路坐标"。要让它们对齐，必须先做"空间字典"（Step 2）。

#### Step 2：空间字典

把全岛划成"三层"空间结构：

- 5 个 Region（大区）
- 55 个 Planning Area（规划区）
- 332 个 Subzone（子区）

每个 Subzone 都有"我在哪个 Region、哪个 PA"的双重身份。

#### Step 3：每个小区早高峰出发多少人（产生量 P_i）

每个 Subzone 的"早高峰产生量"由两个东西推算：
1. 这个 Subzone 有多少户（来自 HDB 住房数据）
2. 平均每户有几个"上班族"（来自 Census）

P_i = 该 Subzone 的家庭户数 × 平均每户早高峰出行数

#### Step 4：每个小区早高峰去多少人（吸引量 A_j）

每个 Subzone 的"早高峰吸引量"主要由：
1. 这个 Subzone 有多少企业（来自 ACRA）
2. 这些企业共能容纳多少就业（Census 表 118 控制）

A_j = 该 Subzone 的就业岗位数（按企业规模加权）

#### Step 5：用"双约束重力模型"算 OD 出行量

借鉴万有引力公式：

```
T_ij ∝ (P_i × A_j) / 距离^衰减
```

然后用 **IPF**（迭代比例拟合）调整，保证每行/每列加起来 = 推算值。

这就是**初始 OD 矩阵**——谁从哪儿出发，去哪儿，去几次。

#### Step 6：算每条出行要多久（自由流通行 + AM 峰通行）

两个版本的通行时间：

- **自由流（C^FF）**：凌晨没车时的通行时间——最快
- **AM 峰通行（C^AM）**：早高峰的实际通行时间——更慢，受 LTA 速度区间约束

### 第二阶段：搭建仿真路网 + 生成 23 万"虚拟人"

#### Step 7：把真实路网转成仿真格式

OSM 的"路在哪里"翻译成 MATSim 能读的 `network.xml.gz`。

这一步要：
- 清理断头路（路网里有些路只连了一头，车开进去就出不来）
- 标注每段路的车道数、限速、通行能力
- 区分道路等级（motorway / arterial / slip）

#### Step 8：生成 236,044 辆虚拟车

按真实人口 / 出行比例，仿真里要跑这么多虚拟人：

- **真实人口**：约 592.5 万人（HDB + Census）
- **早高峰出行人口**：约 117 万（Census 出行率推算）
- **采样到仿真**：本项目用 236,044 辆虚拟车（每个代表约 5 个真实出行者）

虚拟人不是均匀随机生成的——每个虚拟人从特定 Subzone 出发，到特定 Subzone 结束，按 Step 5 算出的 OD 矩阵分布。

#### Step 9：把每个虚拟人接到最近的路网上（端点吸附）

虚拟人的出发地 / 目的地是 Subzone（一个多边形区域），但路网是"线"。要把 Subzone 中心点 → 最近的路网点 对接上，每个虚拟人才能"上路"。

这步叫**端点吸附**——本来断头的虚拟人，被"贴"到最近的路网上。

### 第三阶段：让虚拟车跑早高峰 + 对账

#### Step 10：第一次仿真

MATSim 让 236,044 辆虚拟车在仿真路网上跑早高峰（07:00-09:00）。

但不是"跑一次就完"——MATSim 会迭代：
- 第 1 轮：每个虚拟人按初始计划跑
- 第 2 轮：根据上一轮路况，重新选路
- ...
- 第 20 轮：基本稳定

20 轮迭代之后，仿真结果用于后续对账。

#### Step 11：把仿真结果按 576 个摄像头断面映射、对齐

仿真里没有"摄像头"——只有"边"（link）。

要对比仿真和实测，必须先把 576 个摄像头和仿真里的边对应起来——这就是**Crosswalk**（路段映射表）。

本项目用 `crosswalk = 7.3.6A`：
- 576 个摄像头 → 3,037 条匹配边（平均 5.54 条/摄像头）
- 覆盖 96% 摄像头
- 纯度 100%（没有"匹配到错误等级"的情况）

#### Step 12：比对仿真 vs 实测

对每个摄像头断面：

```
Sim/Obs = 仿真流量 / 实测流量
```

理想值 = 1.0。

v1.0 的全局 Sim/Obs = **0.9993**（几乎完美）。

但分断面看仍有偏差：
- 154 个断面 Sim/Obs > 1.5（仿真高估）
- 210 个断面 Sim/Obs < 0.5（仿真低估）
- 正负抵消后，总和接近 1

这就是 v1.0 的**空间残差**——全局看完美，分布上看仍有偏差。

### 第四阶段：排查差距根因（v1.0 已冻结）

#### Step 13：逐轮排查

仿真和实测的偏差来自哪里？可能原因包括：

1. **拥堵反馈系数**：出行者遇到堵车会换路或推迟出发的程度
2. **道路容量系数**：仿真里路"有多宽"——给得太宽则车太少还跑得顺
3. **路径选择**：每个虚拟人怎么选路——给得过激则车都往高速挤
4. **路网表达**：路网细节够不够——匝道、高低速切换够不够细
5. **车型构成**：仿真里全是小车，实测有大车——大车占空间更多
6. **信号灯**：仿真里没建模信号灯——但实测堵车时信号灯影响很大

每个嫌疑都做独立实验，逐步锁定"哪个是主因"。

#### Step 14：调整参数 + 重跑 + 验证

每调一组参数，重跑仿真，看 Sim/Obs 变化。

- 调对了 → Sim/Obs 改善
- 调错了 → Sim/Obs 恶化
- 调到一定程度后 → 进入"参数不可辨识"区（再调也不变了）

v1.0 就是这样**逐步收敛**出来的——从 0.6 → 0.7 → 0.8 → 0.9 → 0.999。

## 第八章：常见问答

### Q1：为什么全局 Sim/Obs = 0.999 但空间分布仍有偏差？

**A**：仿真和实测的"总和"几乎完美抵消——154 个高估断面和 210 个低估断面正负相消。每个断面本身仍有 32% 偏差，但全局加起来是 0.999。

这是"过拟合"的危险信号——为了让总和接近 1，可能在某些断面上"过度修正"。v1.0 通过"双口径并报 + 不藏空间残差"的方式规避这个风险。

### Q2：v1.0 还能改吗？

**A**：根据项目约定：
- v1.0 的"输入与算法锁"已冻结
- 任何修改必须产生 **v1.1**（不允许就地改 v1.0）
- 7.9 系列残差归因**不重开 v1.0 动力学参数**

### Q3：仿真参数这么多，怎么知道"现在用了哪一组"？

**A**：查看 `FINAL_MODEL_MANIFEST.json`（在 `reports/final_model_7_8/` 下）。里面有：
- `f_work` = 1.180222（工作点需求缩放）
- `lambda_ref` = 0.075（λ 敏感度中心）
- `scale` = 2.29897（扩样倍数）
- `f_cap` = 1.0（容量系数）
- `route_choice` = `R01_rc_min`（路径选择策略）
- `sim_agents` = 236044（虚拟车数）
- `crosswalk` = `7.3.6A`（路段映射表版本）
- `calibration_target` = 0.8589732（校准目标 Sim/Obs）
- `validation` = `W01`（验证锚点）
- `spatial_residual_status` = `UNRESOLVED_STRUCTURAL_LAYER`（空间残差状态）

### Q4：还有哪些数据没用到？

**A**：
- **LTA 分车型交通量**：本地没有，需向 LTA 申请

- **信号灯真实配时**：仿真里完全没建模信号灯，但 LTA 实测配时是有的（受 `SIGNAL_MECHANISM_ABSENT` 判决影响）
